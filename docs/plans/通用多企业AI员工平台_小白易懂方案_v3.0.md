## 1. 60 秒看懂

我们不是先给某一家企业做定制软件，而是先造一套能反复交付给不同企业的标准 AI 办公产品。

这套产品想做到：

- 每位员工都有自己的 AI 助手、会话、记忆和权限；
- 几百人共享一套计算资源，不需要每人一台 VPS；
- 企业可以统一管理知识、AI 工作方法、预算和正式成果；
- 上级默认不能随便翻看员工私人会话和个人记忆；
- AI 可以查资料、解释指标、生成草稿和准备动作；
- 高风险正式动作必须由真正有业务权限的人确认；
- 每家企业的数据、人员、权限和系统连接相互隔离；
- 最后可以把同一产品交付给不同企业，而不是每次重做。

整个工程分成：

| 阶段 | 大白话 | 项目数 | 使用企业内部资料 |
|---|---|---:|---:|
| P0 | 画图纸、定红线、准备考试 | 4 | 否 |
| P1 | 把标准产品主体建出来 | 19 | 否 |
| P2 | 把它变成能正式交付的安全产品 | 6 | 否 |
| P3 | 为一家真实企业办理入住 | 8 | 是 |
| 合计 | 37 个可以单独负责、单独验收的工作包 | 37 | — |

37 个项目不是 37 个软件、37 台服务器、37 个代码库、37 名员工或 37 条审批流程。一个人可以承担多个建设角色，系统也会尽量保持简单。

## 2. 你是什么身份

你是这套产品的**外部 Product Owner（产品所有者）**，不是某家目标企业的员工。

你负责：

- 决定产品方向和阶段范围；
- 每个阶段结束时查看冻结验收包；
- 选择批准、带排除项批准、退回或暂缓；
- 决定是否把方案拿给其他人看。

项目进度看板只记录你的最终阶段决定，不复制企业内部讨论和签字流转；但平台必须保存必要的企业授权引用、范围、有效期、C3 启用记录和每次正式业务决定证据。

整个系统有三类不能混用的权力：

| 权力 | 谁作出 | 管什么 |
|---|---|---|
| 产品阶段批准 | 你 | P0、P1、P2、P3 是否通过 |
| 企业运行授权 | 目标企业正式授权的人 | 哪些身份、资料、模型和系统连接可以进入 Tenant |
| 某次业务决定 | 企业中真正有该业务权限的真人 | 某一份订单、报价、邮件、合同或系统动作是否执行 |

但是，你的阶段批准不会自动让你获得某家企业的：

- 员工身份；
- 内部文件；
- 数据库权限；
- OA、ERP 或 BI 权限；
- 订单、合同、报价或审批的正式操作权。

进入 P3 后，企业资料和系统接入必须由目标企业正式授权的人提供。真正写入企业系统的动作，也必须由企业中本来就有该业务权限的人确认。你仍然只负责最后的产品阶段验收。

## 3. 用“通用办公园区”理解四个阶段

```mermaid
flowchart LR
  P0["P0：图纸、红线、考试题"] --> G0["你批准 G0"]
  G0 --> P1["P1：建房间、门禁、档案室和 AI 服务"]
  P1 --> G1["你批准 G1"]
  G1 --> P2["P2：消防、保险柜、备用电源和交付包"]
  P2 --> G2["你批准 G2"]
  G2 --> P3["P3：为一家真实企业办理入住"]
  P3 --> G3["你批准 G3"]
```

- P0—P2 像先建一座标准办公园区，只让三家完全虚构的公司进去做测试。
- P3 才像让一家真实企业正式入住，分批办理员工、文件、门禁和系统接口。
- 换下一家企业时，新建独立企业空间和配置，不重盖整座园区。

### P3 前可以收集什么

可以提前收集企业已经公开的官网、公开年报、新闻、产品目录和招聘信息，但必须记录来源和日期，并放在独立的“公开背景资料区”。

公开背景资料：

- 不能混进虚构测试数据；
- 不能拿来创建真实员工和权限；
- 不能当作订单、库存、审批或 KPI 事实；
- 不能打进标准产品安装包；
- P3 后仍要由目标企业正式确认，才能进入该企业的内部知识。

## 4. 什么叫“做完”

下面四句话必须分开：

1. **计划写完**：我们知道要做什么。
2. **代码做出来**：功能已经实现。
3. **证据验证通过**：正常、错误、越权、恢复和回滚测试真的通过。
4. **阶段被你批准**：冻结版本的数字指纹与你批准的完全一致。

写完这两份方案只属于第 1 类，不代表 37 个项目已经工程验收。

每个阶段结束时，系统会把不能再修改的验收材料打成一个“冻结包”，再计算唯一数字指纹。你批准的是这个准确版本。内容改变后，必须重新生成新版本，不能沿用旧批准。

## 5. P0：画图纸、定红线、准备考试

P0 不需要 GPU、复杂生产集群或任何企业内部资料。它只建设规则、合成测试场和自动门禁。

### P0 的 4 个项目

| ID | 小白名称 | 实际做什么 | 你会看到什么 | 怎样算过关 |
|---|---|---|---|---|
| F01 | 产品总图和阶段规则 | 统一名词、37 项边界、四阶段入口出口、证据包和你的审批办法 | 产品词典、总图、阶段清单、审批样例 | 关键词没有歧义；你的阶段批准与企业运行授权彻底分开 |
| F02 | 三家虚构企业和真实资料拦截门 | 自动生成虚构企业、员工、资料、权限和系统返回；扫描真实资料与密码 | 三套可重复生成的测试数据、扫描报告 | 至少三家虚构企业可重复生成；真实企业资料和凭据会被自动拦住 |
| F03 | 产品各部分的插头标准 | 先规定界面、后台、模型、工具、连接器和审计怎样交换信息 | 接口说明、假接口、兼容测试 | 不兼容修改会被自动测试挡住；假接口不能冒充真实接入 |

P0 绝对不能：

- 使用真实或“脱敏后的”企业内部资料；
- 连接真实 OA、ERP、BI 或企业网络；
- 把企业官网资料混入虚构测试数据；
- 采购 GPU 或先搭复杂生产集群；
- 深度定制漂亮聊天界面；
- 把一次性实验说成 P1 正式功能已经完成。

### 你怎样批准 G0

只有 F01—F04 全部过关，才能把 P0 冻结包交给你。你确认：

- 37 项和四阶段已经固定；
- 三家虚构企业能生成；
- 真实企业资料会被挡住；
- 核心插头标准和安全考试已经准备好；
- 冻结包数字指纹正确。

批准后才能进入 P1。

## 6. P1：把标准产品主体建出来

P1 像把园区的房间、门禁、档案室、服务台、管理室、AI 调度和水电表建出来，但仍然只让虚构企业使用。

### P1 的 19 个项目

|---|---|---|---|

| C08 | 平台运行总账 | 记录任务、会话、运行、成果、工具调用和待执行动作 | 一次运行可以完整还原；崩溃重试不会重复执行 |
| C09 | 员工个人记忆 | 管候选记忆、本人确认、纠正、删除和过期 | AI 只能提出候选；本人确认后生效；个人记忆不能覆盖企业正式事实 |
| C10 | 企业资料收件和编目 | 检查文件、解析内容、登记来源、版本、有效期、密级和权限 | 缺少必要资料的文件不能发布；原件到答案来源可以追踪 |

| C12 | AI 工作调度员 | 按固定步骤分类、查知识、用工具、生成草稿、复核和等人确认 | 每一步可解释；AI 不能自己决定权限、预算、上云和高风险批准 |
| C13 | AI 工作方法商店 | 提交、测试、批准、发布、灰度、撤回和回滚 Skill | 未测试、未批准或已撤回的 Skill 不能运行；P1 不运行任意脚本 |
| C14 | 模型调度中心 | 在允许的模型中按质量、成本和速度选择 | 先检查权限、敏感级别和数据地区；敏感任务不能偷偷改发云端 |
| C15 | 人工确认保险箱 | 冻结完整候选、展示差异和风险，在 P1 用虚构人测试决定机制 | 任何字段变化都让旧决定失效；P1 测试决定不能产生真实外部动作，也不能带入 P3 |
| C16 | 企业工具服务窗口 | 只开放有名称、有范围的窄业务操作 | 每次调用重新鉴权；没有任意 SQL、任意网址、万能工具和长期生产账号 |
| C17 | 通用连接器模板实验室 | 为协同、业务系统和 BI 做三类标准插头和假接口 | 只有模板和模拟接口；没有真实地址、凭据或企业网络；攻击测试通过 |
| C18 | 不能随便改的证据链 | 串联身份、授权、模型、知识、Skill、工具、决定和结果 | 业务管理员不能修改或删除历史证据；尽量不保存对话和文件正文 |
| C19 | 运行仪表盘和费用表 | 记录速度、故障、用量、配额和成本 | 一次请求能跨模块追踪；费用能按企业、任务和模型核对 |

### 一名虚构员工怎样完成任务

```text
登录
→ 系统确认他属于哪家虚构企业、是谁
→ 检查他能不能做这件事
→ 只在他有权看的资料中搜索
→ 只在允许的模型中选择

→ 保存审计和费用记录
```

### 你怎样批准 G1

你会看到：

- 三家虚构企业已经真实运行，每家有多个虚构用户和角色；
- 数据库、向量、文件、缓存、搜索、工具和恢复后的跨企业泄露为零；
- “登录→AI→知识或工具→虚构人工决定→审计和计费”可以完整重放，且没有真实外部动作；
- 任意代码仍然关闭；
- 所有企业系统连接器仍是模拟状态。

这些全部通过后才批准进入 P2。

## 7. P2：把系统变成能正式交付的产品

P2 像给园区做消防、电梯、保险柜、备用电源、建材合格证、压力测试和标准施工包。

### P2 的 6 个项目

| ID | 小白名称 | 实际做什么 | 怎样算过关 |
|---|---|---|---|
| O01 | 一次性安全工作间 | 每个不可信代码任务临时创建独立小型虚拟环境 | 一任务一环境；默认断网；看不到宿主机和长期密码；任务后彻底销毁 |
| O02 | 密钥保险柜和临时工作证 | 保存秘密并给系统服务发短期、有限权限的凭据 | 跨企业、服务和环境读取全部拒绝；秘密不进入代码、镜像、聊天和日志 |
| O03 | 软件零件验货和封条 | 固定版本、生成材料清单、扫描漏洞、记录来源并签名 | 只有固定版本、来源清楚、签名和检查通过的制品能运行 |
| O04 | 安装、升级和回滚包 | 制作开发演示包、生产安装包、升级、数据库迁移和回退 | 空环境可以重复安装；升级和回滚通过；默认包没有任何企业资料和凭据 |
| O05 | 备份、恢复和灾备 | 对数据库、文件、制品和配置进行真实恢复演练 | 只有真正恢复成功才算备份有效；恢复后权限、隔离和审计仍然正确 |
| O06 | 压力、故障和灰度发布 | 测两倍峰值、长时间运行、依赖故障、灰度和自动回滚 | 默认通过两倍峰值 60 分钟、目标负载 72 小时、故障恢复和自动回滚 |

P2 绝对不能：

- 把普通容器说成强隔离小型虚拟机；
- 让沙箱承担订单、合同、报价或审批的正式写回；
- 把“备份任务成功”说成“恢复成功”；
- 运行无固定版本、无来源或缺少必要材料清单的制品；
- 把真实企业资料打进标准安装包；
- 仅因赶工随意缩短长时间稳定性测试；
- 把合成测试通过说成任何真实企业已经上线。

### 你怎样批准 G2

你会看到：

- 产品可以从空环境重复安装、升级和回滚；
- 一次性安全工作间、密钥、签名制品和发布门都通过；
- 两倍峰值、长时间运行、故障和自动回滚达到标准；
- 数据库和整套产品真的恢复成功；
- 发布包没有任何企业名称、员工、资料、地址、密码或真实连接器；
- P0/P1 的安全能力在正式发布版本上重新测试，没有退步。

这些全部通过后，才第一次允许进入真实企业接入阶段。

## 8. P3：为一家真实企业办理入住

P3 是第一次允许企业内部资料进入，但不是把所有资料一次性扔给 AI。

正确顺序是：

1. 先确认目标企业和正式授权；
2. 创建一个全新的真实 Tenant；
3. 冻结数据和隐私规则；
4. 分批接身份、知识和必要系统；
5. 先小范围真实试点；
6. 能停止、回滚、导出和删除后再验收。

密码、Token、私钥和数据库连接串永远不能发进聊天或方案文档，只能由目标企业授权人员放进密钥保险柜。

每家企业还要选择隔离强度：

| 档位 | 大白话 |
|---|---|
| I1 | 共享计算和数据库集群，但用强制门锁、独立文件区、密钥区和恢复测试隔开 |
| I2 | 共享部分计算，但每家企业有独立数据库、文件、密钥和备份 |
| I3 | 使用同一个标准产品版本，为该企业建立独立数据面或独立部署 |

无论选哪档，都不能为企业改出一套专用核心代码。降低隔离档必须重新取得企业授权并完整复测。

### P3 的 8 个项目模板

| ID | 小白名称 | 实际做什么 | 怎样算过关 |
|---|---|---|---|
| T01 | 企业入住和数据规则 | 核验授权、冻结接入包、新建真实 Tenant、选择 I1/I2/I3 隔离档、确定数据和隐私政策 | 授权与接入包指纹有效；隔离和允许/拒绝规则通过；文档没有明文密码 |
| T02 | 真实员工和组织门禁 | 接企业登录、组织、角色和员工入调离 | 员工映射到稳定编号；跨部门、兼岗、调岗、离职和撤权测试通过 |
| T03 | 企业知识和工作方法 | 分批接入有负责人、有版本、有权限的资料和 3—5 个 Skill | 无权资料不进入；来源位置正确；过期、撤回和删除能够传播 |
| T04 | OA/协同系统实例 | 为这一企业配置审批或协同系统的快照或窄只读连接 | 默认最多到只读和准备候选；本项目不能直接正式提交 |
| T05 | ERP/业务系统实例 | 为订单、库存、交期等建立窄只读接口 | 不给任意 SQL 或数据库账号；事实仍在原系统；正式提交交给 T07 |
| T06 | BI 和 KPI 指标实例 | 读取企业已认证的指标、口径和截止时间 | BI 永远只读；不重新发明指标；不以聊天量或 Token 暗中考核员工 |
| T07 | 受控正式写回 | 对 OA/ERP 类候选动作进行企业授权、真人确认、提交和回读 | 授权、只读证据和准备操作必须属于同一家企业的同一个连接实例；参数变化重批；重复请求不重复执行 |
| T08 | 小范围真实试点和退出 | 选一个场景、小批用户、培训、支持、灰度、回滚、导出和删除 | 质量、效率、安全、恢复和成本达标；能独立停用和退出 |

### 如果暂时接不了 OA、ERP 或 BI

完全可以以后再接：

- 对应 Connector 保持 `C0（未连接）`；
- 首批场景不需要它时，可以预先写成 `NOT_IN_SCOPE（本次不做）`；
- “可选”只表示尚未启动；一旦开始建设、创建连接实例或被真实场景使用，就自动变成必须通过；
- 不能把“暂时不接”写成“已经完成”；
- 如果主场景必须依赖它，则该场景不能假装通过；
- 等企业正式接口和授权具备后，再单独升级；
- 每家企业、每个系统的状态彼此独立；
- BI/T06 永远不能升级为写回。

### 真实连接的四个等级

| 等级 | 大白话 |
|---|---|
| C0 | 完全关闭，没有企业地址、密码和网络 |
| C1 | 经授权的文件或快照 |
| C2 | 正式、窄范围、只读接口 |
| C3 | 对特定 OA/ERP 类动作启用受控写回 |

C3 不是每个企业和每个系统都必须达到的目标。很多企业长期只用 C2 更安全。

### 你怎样批准 G3

你会看到：

- 目标企业授权和接入包指纹；
- T02—T07 最终哪些是 `REQUIRED（必须通过）`、哪些是 `NOT_IN_SCOPE（本次不做）`；任何已启动的“可选项”必须转成 REQUIRED；
- 因为 T08 是小批真实员工试点，T02 真实身份和撤权必须通过；
- 真实员工、知识、权限和需要的连接器测试；
- 一个小范围真实场景的质量、效率、安全、成本和恢复结果；
- 停止、回滚、导出、删除和连接器关闭证明；
- 任何正式写回都由企业中真正有该权限的人批准，而不是由你代替。

## 9. 每人一个私人 AI，为什么不需要每人一台 VPS

员工得到的不是一台专属服务器，而是一套逻辑上的私人空间：

- 自己的稳定编号；
- 自己的会话和个人记忆；
- 自己有权看的知识；
- 自己可以使用的 Skill、模型和工具；
- 自己的配额、费用和审计归属。

大量员工共享平台的普通计算资源。系统每次根据员工身份取回属于他的状态，并执行权限检查。

只有不可信代码任务，才临时创建一个一次性安全工作间；任务完成后立即销毁。这样比给几百人各养一台 VPS 更省资源，也更容易统一升级和管理。

## 10. 上级能管理什么，默认不能看什么

按目标企业正式政策，上级可以管理：

- 部门正式 Skill；
- 模型预算和配额；
- 正式工作成果；
- 工作流和业务规则；
- 已批准的知识和工具；
- 与正式业务动作有关的审计。

默认不能读取：

- 员工私人会话；
- 员工个人记忆；
- 与正式工作成果无关的个人内容。

如果企业确实要设置例外，必须写成明确政策，说明谁、为什么、在什么条件下可以看，并单独留证。不能只靠“我是上级”。

## 11. 四类资料千万不要混

| 类型 | 是什么 | 可以当企业正式事实吗 |
|---|---|---:|
| 个人记忆 | 员工确认的偏好和工作状态 | 否 |
| 企业知识 | 有负责人、版本、有效期和权限的制度/资料 | 在其授权和有效范围内可以 |
| 业务系统事实 | OA、ERP、BI 中的正式状态和指标 | 是，以源系统为准 |
| 公开外部信息 | 官网、公开年报、新闻、产品目录 | 否，除非 P3 被企业正式确认并重新接入 |

订单、价格、合同、认证和 KPI 不能因为某位员工或 AI “记得”就变成正式事实。

## 12. Skill、Tool、Connector、Sandbox 有什么区别

- **Skill**：AI 的工作方法，例如“怎样分析询盘”。它不是权限。
- **Tool**：一个范围很窄的业务操作，例如“查询订单状态”。它不能是万能数据库入口。
- **Connector**：把 Tool 接到某家企业真实系统的受控接头。P0—P2 只有标准接头和假接口。
- **Sandbox**：运行不可信代码的一次性安全工作间。它不能代替正式业务写回。

记住一句话：

> AI 可以建议用什么，服务端决定能不能用，真正高风险动作由有权限的人确认。

## 13. 你每个阶段怎样审批

每个阶段可以多次提交，但每次提交都有一个不能修改的冻结包和数字指纹。你对每一次准确提交只作一次决定：

| 决定 | 含义 |
|---|---|
| APPROVE | 必选项和红线全部通过，批准进入下一阶段 |
| APPROVE_WITH_EXCLUSIONS | 只排除事先声明为非必选的范围 |
| RETURN | 退回修改；修改后生成新指纹重新提交 |
| HOLD | 暂缓；不开放下一阶段 |

不能被排除的红线包括：

- 跨企业或跨用户泄露；
- P0—P2 提前进入企业内部资料；
- 未授权敏感数据上云；
- 无真人有效决定的高风险执行；
- 真实连接器跳级；
- 密码和长期秘密进入聊天、代码或产品包。

你批准的是产品阶段，不是某次订单、合同、报价、邮件或企业系统写回。

## 14. 需要哪些人

“负责角色”不等于必须增加一个全职员工。一人可以承担多个角色，但每项必须知道谁对结果负责。

| 阶段 | 主要需要的能力 |
|---|---|
| P0 | 产品架构、测试数据、接口契约、AI 安全评测 |
| P1 | 前后端、身份权限、数据隔离、AI/知识、模型、工作流、工具、审计和运行监控 |
| P2 | 沙箱安全、密钥、软件供应链、部署、数据库恢复、性能和发布 |
| P3 | 产品接入人员，加目标企业正式指定的身份、知识、系统接口和业务授权人员 |

如果目前只有你一个人：

- 你可以继续担任唯一 Product Owner；
- AI 可以帮助写方案、代码、测试和证据；
- 但企业生产系统不能只靠你一个人同时完成开发、安全证明、灾备演练和生产值守；
- 进入 P1/P2 时应逐步引入工程、IAM/安全、数据库/SRE 和独立测试能力；
- 进入 P3 时，企业侧角色必须由目标企业正式指定，不能由你替他们授权。

## 15. 大概需要多久

这是一个产品工程，不是几周装完的聊天工具。

| 组织方式 | P0 | P1 | P2 | P3 每家企业 |
|---|---:|---:|---:|---:|
| 只有你协调，加零散外包 | 2—3 个月 | 12—20+ 个月 | 8—14+ 个月 | 4—9+ 个月 |
| 6—10 人跨职能团队 | 1—1.5 个月 | 5—8 个月 | 4—6 个月 | 2—4 个月 |
| 已有成熟平台团队 | 3—5 周 | 4—6 个月 | 3—5 个月 | 6—12 周 |

这些是规划区间，不是承诺。真实企业等待接口、授权和资料整改的时间会另外增加。

## 16. 钱主要花在哪里

真正的大头通常不是模型 Token，而是：

- 工程和安全人员；
- 开发、测试和生产基础设施；
- 模型调用或本地 GPU；
- 身份、密钥、监控、备份和网络；
- 安全测试、许可证和法务；
- 每家企业的接入、培训和支持；
- 上线后的持续运维。

P0 前不应采购 GPU 或复杂生产集群。先用 P0 的测试目标和 P1 的实际用量形成容量画像，再决定买什么。

## 17. 最容易误解的 12 件事

1. 37 个项目不是 37 个微服务。
2. 37 个项目不是 37 名员工。
3. P0—P2 连脱敏真实资料也不能使用。
4. 公开企业信息不等于企业内部事实。
5. 虚构 Tenant 不能原地变成真实企业 Tenant。
6. Product Owner 不是目标企业员工。
7. Product Owner 的阶段批准不等于企业运行授权。
8. 每人一个私人 AI 不等于每人一台 VPS。
9. 个人记忆不等于企业事实数据库。
10. Connector Template、Mock 和 C0 不等于已经接入企业系统。
11. P3 是首次允许企业资料进入，但仍然要分批授权接入。
12. 方案完成、代码完成、测试通过和阶段批准是四种不同状态。

## 19. 小白词典

| 词 | 大白话 |
|---|---|
| Tenant | 一家企业在产品中的独立空间 |
| Synthetic Tenant | 完全虚构、用完可丢弃的测试企业空间 |
| Stable Principal | 不随邮箱或登录系统变化的内部永久编号 |
| AIOS Core | 保存任务状态、权限调用和证据的产品核心 |
| RAG | 让 AI 在有权限的知识中找证据再回答 |
| Agent | 按职责和步骤完成任务的 AI 工作角色 |
| Skill | 被测试、发布和管理的 AI 工作方法 |
| Tool | 一个范围很窄、每次都要检查权限的业务操作 |
| Connector Template | 不含任何企业地址和密码的标准接头图纸 |
| Connector Instance | 某家企业实际配置的一只接头 |
| HumanDecision | 有真实业务权限的人对一个准确对象作的正式决定 |
| Stage Approval | 你对一个产品阶段冻结包作的决定 |
| EvidenceRef | 答案或指标的来源、版本和位置 |
| Sandbox | 每个不可信代码任务临时使用的一次性安全工作间 |
| SHA-256 | 一个文件或验收包的唯一数字指纹 |
| C0/C1/C2/C3 | 未连接、授权快照、正式只读、受控写回 |
| SLO | 系统对速度和可用性作出的可测目标 |
| RPO/RTO | 最多能丢多少数据、多久必须恢复 |

## 20. 你只需要记住的最后五句话

1. P0—P2 先造通用产品，不向你索取企业内部资料。
2. 37 项是可验收工作包，不是 37 套软件或 37 个人。
3. 每个阶段只由你审批，但企业数据和正式业务动作仍由企业授权主体负责。
4. 每人私人 AI 靠身份、数据和权限隔离，不靠每人一台 VPS。
5. P3 才为一家真实企业分批接入人员、知识和必要系统；不能接的系统以后再接。
