# Rebound the Required Check to a mixed-coverage semantic Envelope

- Status: Accepted
- Date: 2026-08-15
- Scope: P0-P2 synthetic-data preproduction Required Check material

## Context

ADR 0023 bounded the hosted model Check to exact Git bytes and 96 KiB. The
post-P1-B11 Profile cascade and Reference Review R0/R1/R2 chain added evidence
that is necessary to understand the current engineering readiness boundary but
is much larger than that cap. In particular, the frozen Reference Review
runtime proof cannot be placed verbatim in the prompt. Appending it, every test
blob, or every later artifact would either exceed the cap or falsely imply that
the model read bytes it never received.

The current Git history also contains no formal collector result bound to the
implementation of this Envelope contract. A result generated before the
implementation commit cannot prove execution of that commit, while a result
that embeds its own later evidence commit would create an impossible cycle.

## Decision

Keep the workflow, provider, model, zero-tool contract and 96 KiB hard cap from
ADR 0023. Replace the old flat material list with one dynamic, closed
`independent-model-review-material-envelope.v1` built only from exact Git
objects. The Envelope distinguishes:

- exact full-file and exact Git-patch bytes visible to the model;
- Git-bound digest and semantic projections visible without source bytes; and
- formal command-level collector results that are not model file review.

No `tests/**/*` or other broad glob is permitted. Test digest coverage is an
exact 21-path allowlist with each blob's mode, length and raw SHA-256. The other
233 test blobs are outside per-path model coverage. A formal full-suite result
may prove the command-level TAP observation for its frozen source tree; it does
not prove per-file model review, source coverage or independent execution of
every helper.

The material is frozen in two additive commits. M1A changes exactly the nine
approved implementation, Schema, prompt, test and ADR paths. The formal
collector runs against M1A's exact commit and tree. M1B then adds only the ten
result, stdout, stderr and runtime-binding evidence files. M1B evidence refers
only to M1A; M1B's commit and tree never enter those files. At Required Check
runtime, a non-persisted Envelope binds M1B and proves that M1A is its strict
parent. This separates implementation, execution evidence and final material
without a digest cycle.

Output-only Schema and semantic mutations may reuse one material object only
when repository identity, head, tree and event base are identical. Git object,
material, topology, provider, location, dirty-worktree and replay boundaries
continue through the outer Required Check adapter. This reuse changes neither
the case set nor the top-level test count.

Each formal command runs in its own POSIX process group. A timeout sends
`SIGKILL` to the whole group and waits for group exit before cleanup. Cleanup
restores owner permissions without following symbolic links, attempts scratch,
npm-config, source-export, Git-history and parent roots independently, and
verifies that every root is absent. Cleanup failures never replace a primary
execution error; they remain ancillary on that error. A cleanup failure after a
successful command fails closed.

The following closed projection is the machine-readable form of this decision.
The builder pins the exact ADR blob before using it; the model receives the
derived semantic projection and the ADR's Git descriptor, not these bytes as
verbatim material.
