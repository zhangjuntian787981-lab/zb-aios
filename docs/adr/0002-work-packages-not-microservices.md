# Treat the 37 projects as work packages, not microservices

The product is decomposed into 29 reusable product work packages and 8 repeatable enterprise-onboarding work-package templates so that each outcome can be owned and accepted independently. This decomposition does not create 37 repositories, services, deployments, teams, or permanent processes: P1 defaults to a modular monolith with a small number of independently operated security and infrastructure components, and a module is split only when isolation, scale, ownership, or lifecycle evidence requires it.
