# 通用产品建设与 P3 企业接入规则 v2.0

日期：2026-07-25

状态：P0—P2 无需提供任何目标企业内部资料

## 当前结论

现在不向产品所有者索取企业名称、员工、部门、制度、内部资料、账号体系、业务流程、KPI、OA、ERP、BI 或其他企业系统信息。

项目先建设一套可以交付给不同企业的通用产品：

1. P0：确认产品边界和技术基线；
2. P1：用合成租户、合成用户和合成知识建设多租户核心；
3. P2：完成产品打包、安全、恢复、压测、沙箱和 Connector Templates；
4. P3：一次性接收目标企业接入包，创建 Tenant，导入真实资料和用户，逐级激活 Connector，并完成真实验收。

P0、P1、P2、P3 的阶段结果都只由外部产品所有者审批。产品不记录其他部门的审批过程；产品所有者自行征求谁的意见，不属于本项目的跟踪范围。

## 角色边界

- 当前用户是“外部产品所有者”，不是目标企业员工。
- 外部产品所有者的阶段审批决定项目能否进入下一阶段。
- 外部产品所有者不会因为这个角色自动成为任何 Tenant 的员工或管理员。
- 目标企业员工只在 P3 创建 Tenant 并完成授权配置后才会出现。
- 企业内部的运行权限由未来 Tenant 配置；它与项目阶段审批是两件事。

## P0—P2 唯一允许的数据

- 完全虚构的企业、部门和员工；
- 合成制度、产品资料和业务案例；
- 合成 OA、ERP、BI 响应；
- 合成权限、审批和审计记录；
- 经过安全生成、不来自真实企业的压测数据。

“脱敏真实数据”仍然属于企业数据，不能在 P0—P2 使用。

## P3 前可以提前提供的公开外部信息

产品所有者可以提前提供或安排收集：

- 企业官网已经公开的介绍；
- 公开工商登记和公开年报；
- 公开产品目录、新闻、招聘信息；
- 公开联系方式和行业资料。

这些内容统一标记为 `PUBLIC_EXTERNAL_CONTEXT`，只用于理解行业和准备接入，不得：

- 冒充企业内部权威事实；
- 创建真实员工账号或权限；
- 激活 Tenant 或 Connector；
- 推断未公开的组织、客户、订单或经营数据。

每条公开信息保留来源、发布日期和采集日期。

## P3 一次性企业接入包

进入 P3 后，由目标企业的授权接入人通过正式渠道一次性提供六类资料；外部产品所有者只审批阶段结果：

1. 企业正式名称、Tenant 代号、部署区域和接入授权记录；
2. 真实用户、部门、角色、登录和入职调岗离职规则；
3. 内部知识目录、版本、权限、有效期、撤回规则和首批 Skills；
4. 数据分级、上云、隐私、保留、删除和审计规则；
5. 企业系统目录、正式接口、测试环境、字段、新鲜度和回滚条件；
6. 一个真实主场景、3—5 个任务、案例、人工基线、成功指标和停止条件。

密码、Cookie、Token、私钥、生产连接串和生产数据库备份在 P3 也不能交给 AI；它们只能进入批准的密钥管理系统。

首次激活企业 Connector 时必须引用企业接入授权记录并绑定接入包 SHA-256 哈希。该引用只证明接入有合法前提，本项目不跟踪企业内部的审批过程。

## 产品化规则

- 企业差异只能通过 Tenant 配置、策略、知识包、Skills 和 Connector Instances 表达；
- 不为某个企业 Fork 一套独立核心代码；
- 不在代码里写死企业名称、部门、工号、系统名称、资料目录或审批流程；
- Connector Template 是通用能力，Connector Instance 是 P3 的企业专属激活；
- 每个 Tenant 的身份、知识、记忆、文件、密钥、日志和预算隔离；
- 默认产品包不含任何企业内部数据、凭据或网络地址。

## 阶段审批

每个阶段只生成一份冻结验收包，外部产品所有者选择：

- 批准并进入下一阶段；
- 批准但排除列明项目；
- 退回修改；
- 暂缓。

审批记录绑定阶段、版本、内容哈希、审批人和时间。其他人员的意见由产品所有者自行处理，本项目不建立额外审批节点。
