# P0 实施入口

状态：`DRAFT_AWAITING_BUSINESS_CONFIRMATION`

P0 是“确认边界并证明可以安全开工”，不是 P1 功能开发，也不代表平台、知识库或公司系统集成已经完成。P0 的目标是形成可复查的范围、身份、权限、数据、接口、风险和阶段门证据；证据不足时必须显示 `BLOCKED` 或 `UNKNOWN`，不能用推测补齐。

当前治理事实：截至 2026-07-25，只有 1 名项目提议人在做非生产准备，公司尚未批准进入 P0。执行赞助人、公司项目负责人、业务 Owner、资料 Owner 和身份/安全 Owner 均未任命。第一项阶段门是总经理书面批准 P0 并完成实名任命。

人工确认采用集中模式：AI 先给出推荐默认值，业务、资料、IT 和安全 Owner 只核实本领域事实并接受责任，之后由总经理书面指定的 P0 集中审批人一次性审批冻结包。总经理授权、Owner 事实真实性、技术测试结果和 P1 最终 Go/No-Go 不能被 AI 推荐或未获授权的个人签字替代。资料清单和推荐默认值见 [`materials-and-recommendations.v1.md`](materials-and-recommendations.v1.md)。

工程基线见：[中宝企业 AI 员工平台：完备工程级方案 v3.0](../../outputs/中宝企业AI员工平台_完备工程级方案_v3.0.md)。

## 当前允许

- 使用纯合成身份、资料和业务数据制作本地 PoC 与契约测试。
- 起草并评审稳定 `principal_id`、厂商无关 `operation_id` 和唯一 `contract_version`。
- 起草身份 BFF、权限矩阵、来源标签、威胁模型、No-Go、SLI/SLO 和验收测试。
- 盘点现有 IdP、数据库、对象存储、KMS、审计和监控能力，并把未知项保留为未知。
- 核验候选开源组件的版本、镜像摘要、许可证和安全公告。
- 在公司明确纳入范围后，登记经 Owner 批准的资料或 Snapshot；未批准材料不得进入试点。

## 当前禁止

- 不进行 P1 的正式功能开发或声称 P1 已完成。
- 不连接任何真实公司业务系统，不保存其生产凭据，不提前开放出站网络。
- 不通过浏览器抓取、共享账号、非正式接口或直连数据库绕过当前限制。
- 不把 Mock、截图、历史文件或 Snapshot 描述成真实来源的当前数据。
- 不自动发送、提交、审批或写回；不实现生产 Outbox、Commit、readback 或补偿。
- 不开放任意代码执行，不让普通员工安装任意插件、MCP Server 或生产 Tool。
- 不在身份 PoC 通过前深度 Fork 员工入口。
- 不让 Prompt、Skill、前端按钮或模型判断代替服务端权限。
- 不把敏感资料发送给未经公司批准的模型。

## 阶段门命令

阶段门的稳定命令接口预留为：

```bash
npm run p0:status
npm run p0:gate
```

预期语义：

- `p0:status`：只读列出每项 P0 证据的状态、来源、Owner、日期和阻塞原因；不得修改证据。
- `p0:gate`：只读执行阶段门。全部强制证据通过时退出码为 `0`；存在缺失、未知或待公司确认时退出码为 `2`；发现凭据、出站网络、真实读取或提前开放 P1 时退出码为 `3`。

这两个命令现在已经实现。当前基线应返回 `NOT_READY`：它证明阶段门能够阻止误进 P1，不代表 P0 已通过。命令无法运行时必须记为 `NOT_IMPLEMENTED/BLOCKED`，绝不能据此宣称 P0 通过。

## P0 阶段门最小证据

以下证据全部具备后，才可进入 P1：

1. 总经理书面批准进入 P0，并实名任命执行赞助人、公司项目负责人和跨部门责任人。
2. 总经理书面指定 P0 集中审批人和 P1 阶段门审批人，授权范围和证据可复查。
3. AI 推荐包已冻结；业务、资料、IT 和安全 Owner 已完成一次性事实核实。
4. 获授权的 P0 集中审批人一次性批准推荐包，审批记录绑定版本、完整内容哈希和排除项。
5. 唯一试点流程、业务 Owner、资料 Owner、成功指标和人工基线已确认。
6. 试点人员名册、身份来源、稳定 `principal_id` 和调岗/离职撤权流程已确认。
7. 数据分级、上云边界、保留规则和“私人”的含义已确认。
8. 知识、工具、执行、审批四张权限矩阵包含允许与拒绝样例。
9. 首批批准资料、版本、ACL、有效期和可验证案例具备 Owner 事实核实证据。
10. 如本期使用 Snapshot 或 KPI，相应 Schema、Owner、字段字典、截止时间和过期规则已确认；未纳入时明确记为 `NOT_IN_SCOPE`。
11. Connector envelope、来源标签和新鲜度规则已经业务、安全和技术共同确认。
12. 身份 BFF PoC 已证明可信主体绑定、短时断言、撤权、密钥轮换和重放阻断中的正式路径。
13. 威胁模型、No-Go、验收测试、SLI/SLO 和恢复草案已评审。
14. 每项有状态依赖都有可验证的复用、采购或建设结论、生产 Owner 和交付日期。
15. 所有 Real Connector 保持禁用、无生产凭据、无生产出站网络。
16. 公司指定的 P1 阶段门审批人完成最终 Go/No-Go。

## 证据边界

- 仓库文件只能证明“文档或实现存在”，不能证明公司已经批准、真实环境已经部署或生产权限已经正确。
- 截图、口头说明、Mock 结果和软件自带功能列表不能单独作为生产能力证据。
- 公司确认类证据至少记录：`evidence_id`、结论、范围、Owner、确认人、确认时间、来源和有效期。
- 技术验证类证据至少记录：运行命令、固定版本或镜像摘要、输入范围、结果、失败项和复现位置。
- `connector-envelope.v1.json` 当前明确是 `DRAFT_AWAITING_BUSINESS_CONFIRMATION`；它只冻结待评审的 Interface，不证明任何 Adapter、Connector 或公司系统已经可用。
- OA、U9、BI 等真实系统的版本、接口、账号和字段不是当前 P0 开工前提，也不得在没有授权的情况下采集或猜测。
